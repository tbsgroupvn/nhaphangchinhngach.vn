## Local Setup

Use Node >=20.19 and a persistent filesystem. The tested machine runs Node 24.3.0. SQLite is a native dependency; install packages on the deployment OS instead of copying `node_modules` between operating systems.

```powershell
npm ci --include=dev
npm run studio:bootstrap
npm run build
node node_modules/next/dist/bin/next start -p 4173 -H 127.0.0.1
```

Open `http://127.0.0.1:4173/admin/`. The bootstrap script creates `.data/installation.json` only when absent and prints its path, not its contents. The owner enters the private `bootstrapToken` from that local file and chooses their own email/password. No default account is installed. Do not send tokens, passwords or provider keys through chat.

The local installation has a private bootstrap file but no owner account created by the agent. Browser tests use independent temporary databases with fixture accounts.

## Configuration

| Variable | Purpose |
| --- | --- |
| `STUDIO_DATA_DIR` | Persistent directory outside `public`; default `.data` under the application working directory. |
| `STUDIO_ORIGIN` | Exact externally visible origin, including scheme and nonstandard port. Required for production behind a reverse proxy. |
| `STUDIO_BOOTSTRAP_TOKEN` | Optional deployment-supplied first-owner token of at least 32 characters; otherwise read from private installation file. |
| `STUDIO_AI_ENCRYPTION_KEY` | Deployment-managed secret: exactly 32 random bytes encoded as canonical base64. Required for AI credential encryption/decryption; no fallback or browser exposure. |
| `NEXT_PUBLIC_SITE_INDEXABLE` | Remains unset/false until explicit release approval. |

Do not put `.data`, installation secrets or raw database copies in Git, `public`, uploaded media or build artifacts. Preserve the data directory when replacing the application release. Windows requires appropriate filesystem ACLs; Unix mode arguments alone do not establish Windows ACL security.

## Authentication Boundaries

- Sessions use random opaque tokens, HttpOnly cookies and server-side revocation. Cookies are Secure on configured HTTPS origins and SameSite Strict. Loopback HTTP is supported for local preview.
- API handlers enforce their own session/capability checks. Mutations validate Origin and bounded JSON bodies. Privileged writes revalidate the original session against the current database inside the write transaction.
- Roles: admin controls publication/settings/users; editor edits drafts; SEO edits metadata through a dedicated metadata-only mutation and cannot change body copy or publish; viewer reads. SEO changes require the current document version and still wait for admin publication. Do not infer authority from UI state or client headers.
- Team updates require the target user's opaque `revision` returned by the API. It is persisted in the existing `updated_at` column and strictly increases even for same-millisecond/backward-clock writes. A stale update returns 409 before changing permissions, revoking sessions or recording success. The team screen retains the pending role and compares the latest role/status, with explicit server/local choices. Successful permission/status changes still revoke the target's sessions; the last active administrator remains protected. Portable website restore never replaces accounts or these stamps.
- Login attempts are limited per account, and concurrent password derivations are bounded. **Deploy a trusted ingress per-IP throttle before exposing this publicly.** The application intentionally does not trust arbitrary forwarded-IP headers and does not use a shared anonymous-client bucket that could lock out every user.
- The former demo CMS HTML, fake Gemini API, diagnostic newsletter/analytics routes, old lead-collection APIs and legacy placeholder content APIs are retired. They do not grant access via the old JWT or localStorage credentials.
- This is not a whole-repository security certification. Dependency review, existing secret exposure assessment, HTTPS, ingress rules and production operations remain release gates.

## Content Persistence

Initial service, industry and article copy is imported once from `src/data/marketing.ts`. The thirteen fixed-page layouts import their copy once from `src/data/fixed-page-seeds.json`, with a separate marker so an existing Studio database receives them without reseeding edited articles. Seed markers prevent unpublished content from being recreated on restart. After seeding, change documents through Studio, not by modifying seed arrays.

All 24 seeded release routes are fixed in the editor: the initial seed revision reserves their paths during save/publish/restore. New articles retain editable slugs; publishing a slug change now creates an atomic 308 redirect from the previous published URL. Original template URL changes require a code/template migration, not a draft field edit. Fixed template types cannot be created through the content API. Text, linked destinations, images, process steps, cost tables, FAQ answers and policy paragraphs are editable in their defined slots. Unknown/missing slots and unsafe image/link paths are rejected; the homepage must retain a hero image. The template registry and React layout must be migrated together when introducing a new slot; this is structured copy management, not arbitrary layout building. Shared contact/navigation/footer belong to site settings; reusable prose and journey copy belong to the shared template workspace below.

Unsaved content/SEO edits use the pinned [Next navigation guard](https://github.com/LayerXcom/next-navigation-guard) for router/history navigation and the browser unload prompt. Logout confirms before revoking a session when unsaved changes are present. Recheck these integration tests when upgrading Next or the guard library.

Draft and published payloads are separate. Saving and restoring change the draft only. Publishing is an explicit admin action; publication, revision and audit event commit together. Every update supplies the expected version and returns HTTP 409 on stale data or conflicting routes. Public routes, related-item lists and metadata read only publication snapshots.

Public content currently renders dynamically to avoid stale publication data. Publishing also invalidates the Next layout cache. Global noindex overrides a document's indexable setting in this preview. `/studio-preview/[id]/` renders the saved draft through the actual public components, requires a valid Studio session, uses noindex and private/no-store headers, and denies framing. The old editor preview URL redirects there. There are no anonymous draft-sharing links.

Do not copy a live WAL database file by itself. Use the portable workflow below for website data. A content-history restore changes only its draft; a full website-backup restore intentionally replaces both saved drafts and public snapshots.

## SEO Workspace

`/admin/seo/` separates saved-draft findings from the last scan of published HTML. Findings link directly to the document's SEO tab. An unscanned or failed page is not reported as clean; changing a document revision or any publication snapshot marks prior HTML results stale. Scans never publish content.

HTML scanning requires `STUDIO_ORIGIN` to name this application's reachable origin. Local example: `http://127.0.0.1:4173`. It must resolve back to the same website/database, not the old live website or another environment. The scanner fetches only stored public paths, sends no session cookies and does not follow redirects. Each request has an eight-second deadline and a 2-MiB HTML limit. At most three page scans run concurrently per application process. The UI scans the filtered published pages sequentially; Stop cancels the browser request and prevents subsequent pages, while any server work already started remains bounded by its deadline.

HTML is parsed using pinned [Cheerio](https://cheerio.js.org/docs/basics/selecting/), not executed as a browser. Checks cover the server-rendered main headings, local image existence/alt attributes, internal destinations/anchors and missing main copy. Missing destinations mean absent from the publication inventory, not a verified HTTP 404; external URLs are not crawled. Decorative images explicitly marked as presentation/aria-hidden are excluded from alt warnings. Stored-copy links distinguish a published destination from a URL that exists only in a draft.

Metadata length notices are editorial hints. Google documents that [title links](https://developers.google.com/search/docs/appearance/title-link) and [snippets](https://developers.google.com/search/docs/appearance/snippet) can be truncated or generated differently; the workspace does not claim fixed Google character limits, ranking scores, traffic or Search Console verification.

Keyword tasks persist in SQLite with an associated document, active assignee, due date, status and notes. Admin, editor and SEO roles may manage them; viewers only read. Expected versions and transaction-time permission checks prevent silent overwrites. A conflict requires explicit comparison with the latest server task before keeping local edits or selecting the server version. Related-link suggestions use shared terms in real saved source copy and published target copy, not an AI provider; the suggestions refresh when the publication inventory is reloaded.

Schema v2 adds audit reports and keyword tasks without reseeding or replacing existing content. Preserve the same persistent data directory during upgrades. These reports and tasks contain no provider credentials or session tokens.

## Technical SEO

`/admin/seo/technical/` provides redirect management, Google ownership-verification tokens and publication-driven sitemap/indexing status. All authenticated roles can inspect it; only admins can change these settings because they affect the public website immediately. Every mutation validates origin, current session/permissions, payload and expected version, and writes its audit record in the same transaction. A stale edit offers an explicit local/server comparison without discarding local input. Schema v3 adds redirects while preserving v1/v2 documents, reports, tasks and users.

Redirect sources are exact lowercase internal paths (letters, numbers, hyphens and slash-separated segments). Trailing slashes normalize to one source; query/hash matching, external destinations, encoded traversal, existing draft/live URLs, system routes and legacy aliases are rejected. A target is an existing **published document ID**, not another redirect. This prevents chains/cycles and makes earlier URLs point directly to the latest published slug. New article slug changes leave the current live URL untouched until publication, then save the redirect and publication atomically. Unpublishing a redirect target is refused until its incoming redirects are retargeted or removed. Reusing an old redirected slug also requires removing its redirect first. Managed redirects do not preserve source query strings; campaign/query forwarding is not configured by this workflow.

The server uses [Next.js 307 temporary or 308 permanent redirects](https://nextjs.org/docs/14/app/building-your-application/routing/redirecting), including unmatched root paths and retired service/industry/article URLs. Permanent redirects can be cached by browsers/crawlers; use temporary redirects while a destination is unsettled. The existing static legacy redirects remain owned by code and cannot be overwritten through Studio. Redirect changes invalidate dependent HTML audits; an internal link through a configured redirect is reported as such, not as a missing destination.

Google verification accepts up to ten distinct tokens, one per line in the editor. Enter the `content` token only, not an HTML tag. Existing tokens are retained unless explicitly edited/removed; do not remove another verified owner's token casually. The saved tokens are emitted as escaped `google-site-verification` metadata in the actual page head. This supports a **URL-prefix property**. A Domain property requires DNS verification, as described in [Google's ownership guide](https://support.google.com/webmasters/answer/9008080?hl=en). The UI truthfully says configured/unconfigured and that Google verification/data connection is unconfirmed. It does not log into Google, claim ownership, fetch rankings/traffic, or submit sitemaps automatically.

Effective indexing requires both the deployment release gate `NEXT_PUBLIC_SITE_INDEXABLE=true` and the Studio suspension checkbox to be off. Changing a checkbox cannot override a closed deployment gate. No release gate was enabled in this work. With indexing off, public metadata is noindex, robots disallows all, and the XML sitemap has no URL entries. With indexing allowed, the sitemap includes only published, individually indexable, self-canonical documents, with their publication timestamps. Drafts and alternate canonical URLs are excluded, following [Google's sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap). The admin shows both the current count and the eligible canonical inventory, without claiming those URLs have been indexed by Google. Admin/API/private preview paths stay excluded from robots.

The live site's verification token and Google account have not been configured. Browser acceptance runs use visibly named fixture tokens on an isolated local database only. Release-enabled filtering and suspension are covered by repository tests; actual local HTTP tests preserve the noindex gate. Production verification and any indexing release remain explicit deployment actions.

## Media Library

`/admin/media/` supports uploads, search by name/description/source, a missing-alt filter, image metadata, usage references and guarded deletion. Admins/editors may upload and edit; SEO/viewer roles may inspect. The content editor has image pickers for the main image, Open Graph image and fixed-template image slots. The existing three website photographs remain selectable as code-owned assets, not fictitious uploads.

Uploads accept static JPEG, PNG, WebP and AVIF. Both the declared MIME and actual file signature are checked before decoding with pinned Sharp. The server accepts at most 8 MiB of streamed bytes, applies a 15-second upload deadline, bounds decoding to 20 million pixels, rejects animated/multipage images, auto-orients and normalizes to WebP up to 2400 x 2400 without enlargement. Embedded EXIF/ICC metadata is stripped. Processing is limited to two uploads per process with a five-second pixel-processing timeout; library limits are 2,000 images / 512 MiB of stored normalized data. SVG/HTML, arbitrary file paths and remote URL imports are not accepted. Set matching ingress body/time/rate limits before deployment; application limits do not replace a trusted ingress.

Schema v4 stores the normalized binary and metadata together as SQLite BLOBs. No uploaded filename becomes a filesystem path. Binary/metadata changes and their audit records commit atomically. Preserve the database's persistent volume; portable website backups include these BLOBs. Do not copy only the main database while WAL writes are active. Built-in image files under `public/images/marketing` still belong to the application release.

Authenticated sessions can retrieve uploaded images for private editing/preview. Anonymous delivery requires a current published document reference (including SEO/fixed image slots) or an applied shared-site setting. Responses are `image/webp`, private/no-store and nosniff; knowing a draft-image URL does not grant anonymous access. Unpublishing/replacing the final public reference removes anonymous access. Deletion refuses references in any draft, public snapshot, historical revision or applied shared-site setting, preserving restore-to-draft integrity. History-only images remain private but cannot be deleted through this UI. History pruning is not provided.

Content/SEO writes, publication and individual revision restoration also reject missing built-in image files before recording a new revision. Portable validation requires existing built-in assets for current drafts, public snapshots and shared settings. Historical revisions may retain an old, syntactically safe built-in path that is absent from the current release; the history is preserved verbatim rather than blocking recovery of the whole website. Such an individual revision cannot become the current draft until its code-owned asset is restored. Unsafe paths and missing managed-upload references remain invalid everywhere, including history. Correct a bad current draft through the editor before exporting; do not delete history to repair a backup.

Library metadata edits never silently alter existing public image descriptions. Publication snapshots the current alt text into the document, while authenticated preview shows the current library alt. Republish each affected document when an updated alt should go live. An empty library alt remains empty and is reported by the SEO audit rather than replaced with invented wording. Existing built-in images retain their original template descriptions. Open Graph image alt uses the same published snapshot. HTML audits recognize managed, publicly referenced images as real assets. If the deployment indexing gate is later enabled, robots allows the media delivery prefix while other API paths remain disallowed; the current preview still disallows all indexing.

The metadata editor preserves local input on HTTP 409 and shows the latest server values. Choosing a remote revision refreshes the gallery/filter/reopen state; keeping local input requires an explicit subsequent save against that version. Unsaved close/history/logout navigation has a confirmation. Image pixels, metadata and usage references have database-reopen coverage; browser workflows use isolated fixture accounts and images, not the real preview owner's data.

## Shared Site Settings

`/admin/settings/` is the admin-only editor for business identity, phone/display number, email, Zalo, header/footer logos, default SEO metadata, navigation and footer copy/links. It uses the same media picker and existing logo palette as Studio. All signed-in roles may read the API, but only a currently authorized administrator may apply changes. This is an explicit **Apply to website** action, not a saved draft: confirmation, expected version, validation, persistence and the audit event are one controlled workflow. The API bounds JSON input to 64 KiB and checks same-origin requests. A conflict preserves local edits and requires an explicit local/server choice before another apply. Unsaved navigation/logout prompts remain active.

Phone display must match the dialed number; email and Zalo formats are constrained. Menus/footer destinations must be safe internal published URLs (or managed redirects with published targets). If a destination is later unpublished, it is hidden in the public navigation but retained in saved settings for recovery; remove or repair it before the next apply. Header navigation is limited to six entries with 24-character labels. Three footer columns preserve the approved layout. These settings do not change the canonical domain, server origin, provider credentials, indexing release gate or logo colors.

Managed logos/share images become anonymous-readable only while referenced by applied settings or published documents. Applied settings also guard deletion. Brand-logo alt text uses the business name; the shared social image has an explicit alt field. Removing the last reference makes the managed image private again. Existing built-in logo/photo assets remain part of the release.

Public header/CTA and footer use a page-scoped settings snapshot so client navigation does not mix a persistent root-layout snapshot with fresh server copy. Organization JSON-LD follows that page snapshot and safely escapes user-supplied text; interior titles use the same applied brand. Individual document metadata still takes precedence over site defaults. Applying shared settings invalidates stored/in-flight HTML audits, because navigation, contacts and metadata can change across every public page. Existing browser-prefetched page snapshots are not a real-time push channel; a reload always reads the current configuration.

## Shared Template Copy

`/admin/templates/` manages 117 named business-copy/image/link fields in eight groups: four-stage journey, consultation sidebar, service template and transport table, industry template, article template and preparation brief, sitemap, 404, and shared labels/policy contact. Fields are searchable by label, current copy or key. The registry supplies validated defaults matching the approved presentation. Layouts, stage count/3D mechanics, system-control text and accessibility labels remain code-owned; adding a new kind of layout requires development.

Only admins can apply a global template change. The API authenticates independently, validates same-origin requests and caps JSON at 512 KiB; missing/unknown fields, empty copy, invalid internal paths and nonexistent images are rejected. Expected versions and a transactional audit event prevent silent overwrite. The editor warns on unsaved navigation/logout and compares local/server values on conflicts. Confirmed apply affects consuming public pages immediately, not through an unpublished draft. Already-prefetched browser snapshots require navigation refresh/reload to observe the new configuration.

Template links must resolve to published internal pages or managed redirects when applied. A later unpublish or redirect removal suppresses the affected public CTA while preserving saved values for repair. Uploaded journey images become anonymously deliverable and deletion-protected while referenced by the applied template; removing the reference restores ordinary media access rules. The image's editable template alt field is explicit, not a live read of mutable library metadata. Applying copy invalidates dependent HTML SEO reports and the Next layout cache. Templates are stored in `studio_settings` under `site.templates.v1` and included in portable backups.

## Portable Website Backups

An administrator uses `/admin/backups/` to create and download a `.sqlite` file. Export first obtains a consistent SQLite online snapshot, then copies only explicit business tables/columns into a fresh database. The raw snapshot is private and never downloadable. Export includes all documents with separate draft/public snapshots, revisions, uploaded WebP bytes and metadata, SEO tasks, redirects, shared site/template settings, and technical SEO settings. Default settings are materialized so restoring later cannot silently select different release defaults. Document order is preserved.

The portable file also includes knowledge drafts/approved snapshots, TBS writing instructions and AI generation history with immutable context/results. It excludes users, password hashes, sessions, rate limits, audit logs, provider secrets, request receipts/budgets, arbitrary/operational settings, derived HTML scan reports, installation files, deployment configuration and source code. Built-in images remain in the application release. Keep the downloaded file confidential: it includes unpublished business copy, internal source documents and private images. These archives are structurally validated, not digitally signed; restore only a file whose source you trust.

Restore procedure:

1. Retain the matching application release and its built-in assets. On a new installation, configure a private persistent directory and create the destination owner through normal bootstrap first.
2. Sign in as an administrator, select the archive and choose **Kiểm tra bản sao**. No website data changes at this stage. Inspect source time and counts, and stop editorial writes during recovery.
3. Enter `KHOI PHUC WEBSITE` and confirm the public replacement. The server validates the file again, checks that website data has not changed since review, and requires a fresh pre-restore export before proceeding.
4. Download **Bản sao trước khôi phục**. Check public pages, private drafts, images, contacts and redirects, then rerun HTML SEO scans. To undo, review and restore that pre-restore file through the same workflow.

One transaction replaces the website's business data and records the restore. Any failure before commit leaves the current website unchanged. Current accounts, sessions, installation/provider secrets and local audit log survive; imported revision actor IDs are cleared to avoid misattribution, and unknown SEO assignees become unassigned. Versions advance beyond imported/current and remembered deleted versions, preventing an old editor from overwriting restored data. Publishing rules remain intact: a draft stays private and an unpublished item stays unpublished. The deployment noindex gate cannot be changed by an archive. Already-open/prefetched public pages may require reload.

Completed restore results remain queryable for the job retention period. Repeating the same confirmed job returns its recorded result without applying twice, and the UI reconciles a lost response against this record. Do not interpret a network error as proof of rollback; inspect the recorded status/audit and refresh before another operation. A stale review requires uploading/checking again.

Current format: `tbs-studio` v3, exact trusted SQLite schema v6. Unknown tables/views/triggers, altered schema, credentials, malformed typed data, inconsistent paths/history, absent/invalid images, unsafe redirects and corrupt files are rejected. Imports require all 24 seeded release routes/history. Limits: 1-GiB file, 10,000 documents, 100,000 revisions including restore-generated revisions, 10,000 SEO tasks/redirects, 2,000 images / 512 MiB normalized image data, 500 knowledge sources / 16 MiB combined draft/approved JSON, 500 AI history records / 256 KiB per record, 1-MiB individual serialized content, 512-KiB settings, and 32-MiB individual normalized WebP. There is no automatic cross-version archive migration or content-history pruning; seek a tested migration/archival plan before reaching those limits.

The running database upgrades older versions through v5 knowledge and v6 generation migrations additively while preserving existing website/account/provider data. Retain a protected, deployment-controlled consistent SQLite backup before upgrading; do not copy the main live WAL database alone. Portable v1/schema-v4 and v2/schema-v5 archives are deliberately rejected by this release and require their matching application version or a tested migration. Existing temporary older downloads remain readable until expiry, but do not become compatible restore files. Restoring v3 preserves source draft/approved separation, clears imported approver/AI actor IDs, retains original approval timestamps and raises versions to defeat stale editors. Imported AI history is read-only evidence and cannot be applied; running records become interrupted. Generate a fresh proposal against restored content before applying. Restored approvals represent the archive's old review, not a new review by the destination administrator.

Files and owner-specific job records live below `STUDIO_DATA_DIR/backups` and private settings. Download/review access expires after two hours; expired/orphan files are cleaned during a subsequent operation, not by a scheduler. At most eight retained jobs, one active backup/restore operation, a four-GiB reservation budget and disk-free checks bound temporary work. Upload and archive-validation phases each have a 120-second deadline; SQLite online snapshotting also has a 120-second progress deadline. Configure trusted ingress size/time limits accordingly. Deleting a job revokes access transactionally; failed physical cleanup is retried by orphan cleanup. Filesystem permissions and Windows ACLs remain deployment responsibilities.

This is an on-demand website-data backup, not scheduled/offsite disaster recovery. Retain downloaded archives in the organization's protected backup storage. Separately back up the application release, private credentials and server configuration using deployment-controlled procedures; never publish raw databases or copy only the live SQLite main file. No automatic backup scheduler or external backup destination has been configured by the agent.

## AI Provider Connection

`/admin/ai-assistant/` and `/api/studio/ai/provider/` provide the current connection workspace. Admins may save/replace/clear credentials and explicitly run a paid provider test; editor/SEO roles may read status, and viewers have no AI access. Writes independently enforce session, current permissions, same origin, bounded input and expected configuration version. Local input survives version conflicts until an explicit local/server choice. Changing the saved configuration invalidates the previous test result.

The deployment owner must supply `STUDIO_AI_ENCRYPTION_KEY` through protected server configuration before saving credentials. Use a cryptographically generated 32-byte value encoded as base64, not a password, example key or checked-in value. Retain it separately from the database in protected deployment backups. Credentials are encrypted with AES-256-GCM and random nonces; neither plaintext keys nor encrypted envelopes appear in API reads, rendered HTML, audit data or portable website exports. There is no implicit use of legacy keys, automatic provider account creation or fallback encryption secret.

Enter an authorized OpenAI API key and the exact model ID available to that account, save, then select **Kiểm tra kết nối** and confirm the possible API charge. The probe sends only a short fixed connectivity instruction and a strict `ok` JSON schema, never website content. Success records timestamp, latency and provider-reported token usage. Missing configuration, unsupported models, authentication/rate-limit failures, refusal, incomplete/invalid JSON, timeout and interrupted probes remain explicit failures; successful fixtures do not prove a live connection. Only the fixed official HTTPS endpoint is allowed, with no redirects, external tools or automatic retries. A real smoke test remains required once the owner supplies credentials.

The adapter follows the official [OpenAI Structured Outputs contract](https://developers.openai.com/api/docs/guides/structured-outputs) using Responses `text.format` and validates returned JSON locally. Requests set `store: false`, as documented in [Responses migration guidance](https://developers.openai.com/api/docs/guides/migrate-to-responses); this is not a claim of zero provider retention. Transport caps are 64-KiB serialized input, 1-MiB response and a 20-second total deadline. Probe output is capped at 128 tokens; editorial tasks use the saved generation-output limit (128-8,192). Models without compatible structured-output support fail clearly; no model is guessed or labeled "latest". The first supported provider is OpenAI; Gemini is not yet connected and the retired `/api/gemini` remains unavailable.

Daily limits are installation-wide UTC-day request/token budgets, not currency billing guarantees. A request reserves its complete bounded input byte count plus protocol allowance and output limit before dispatch. Confirmed usage settles that reservation; uncertain failures keep the reservation conservatively. Failed attempts still count toward the daily request limit. Configuration changes and website restore do not reset budgets. One request runs at a time across application processes sharing this SQLite database; an expired 35-second lease permits recovery after interruption. Refresh reconciles a lost HTTP response without automatically making another paid call. Provider billing/spend limits should also be set in the provider account before production use.

To replace an API key, enter the new value and save; a blank key retains the existing one. If the encryption key is lost or changed, the UI reports unreadable credentials; restore the correct deployment key or enter a fresh authorized API key encrypted under the new deployment key. There is no automatic key rotation. **Gỡ kết nối** removes the current application configuration, not already-dispatched provider requests or provider-side credentials. Logical deletion is not secure erasure of prior SQLite/WAL/deployment backups; revoke compromised keys in the provider account separately.

Browser acceptance uses a guarded Node preload under `tests/support`, active only for an explicitly flagged isolated `artifacts/studio-e2e-*` directory. It intercepts the official endpoint without network access and rejects unknown fixture credentials. This fixture is not imported by production code and must never be enabled in deployment. Actual preview credentials, the installation bootstrap file and provider accounts are untouched.

## Knowledge And Writing Instructions

`/admin/ai/knowledge/` manages private, manually entered source text with title, category, supplying person/organization, optional HTTP(S) source URL, tags and optional UTC review-due date. A URL is provenance only: the application never fetches it, follows its links or imports arbitrary files. The library starts empty; no business or legal claims are invented as seed sources. Limits are 500 sources, 24,000 characters per body, ten tags and 16 MiB for all draft/approved payloads. Plain text is escaped when rendered, including HTML-like text and hostile prompt instructions.

Admin/editor/SEO roles can create and revise drafts. Only a current administrator can explicitly approve, withdraw, archive/reactivate or delete a source, and only administrators can change `/admin/ai/instructions/`. Viewers have no AI access. Every write uses the current session, capability, expected version and an atomic audit event. Editing a draft never changes its approved snapshot. Approval explicitly copies the saved draft and records version, time and actor; it does not certify the factual or legal correctness of the source. A due date before today prevents approval and excludes an existing approval from retrieval. A source with an expired approval stays excluded even after reactivation. Remove/archive obsolete sources rather than merely revising their drafts. Active approved sources cannot be deleted until withdrawn or archived.

The editor compares the entire local draft with the approved snapshot, preserves unsaved work on navigation and exposes local/server conflict reconciliation. Archive disables draft editing until admin reactivation. Deletion is explicit and permanent, with version high-water accounting retained for future backup restores. Restoring a website archive restores knowledge and instructions as business data and invalidates old editor versions, but never imports provider credentials or resets usage budgets.

The **Đối chiếu căn cứ** preview performs local lexical retrieval, not an AI generation or paid request. It matches accent-insensitive Vietnamese terms against approved titles/tags/body, allows general company context, excludes archived/expired/unapproved sources and selects at most six sources in at most 20,000 UTF-8 bytes of serialized source context. Each excerpt is original source text, paired with source ID, approved version, title, source name/URL, review date, original approval time and a SHA-256 digest of the approved payload. This is not semantic/vector search, external fact checking, web browsing or a guarantee of relevance. A short or unsupported topic may correctly return no sources.

Writing instructions are versioned business data: audience, tone, terminology and editorial requirements, up to 2,000 characters per field and 12-KB serialized total. They do not directly change public website text. The server separately supplies noneditable boundaries: sources and editable instructions are untrusted; no tool execution/publication, invented legal/tax rates, operating metrics, fleet ownership, customer claims or sales SLAs. Missing evidence must be flagged, with expert human review for legal/tax content. Contextual generation stores these boundaries and approved-source snapshots. Structural validation and restricted capabilities are enforced locally; model-level resistance to all hostile text and factual correctness are not guaranteed.

## Contextual Editorial AI

Open a saved document's **AI** tab or select content from `/admin/ai/generations/`. Seven tasks are available: brief, outline, new draft copy, rewrite, SEO metadata, FAQ and internal links. Brief/outline/links are advisory results; other tasks propose typed replacements of explicitly selected fields. Fixed-template copy, service/industry lists, article sections and individual paragraphs, FAQ collections and SEO title/description are supported. No proposed slug, image, canonical, robots setting or publication action is accepted. All links must reference supplied published document IDs; historical link suggestions are snapshots and need editorial rechecking before use.

Save local content edits before generation. Select up to twelve fields (24-KB serialized total) and enter a brief of 5-2,000 characters. Large collections can be narrowed to individual paragraphs/items; input is rejected rather than silently truncated. Do not select both a collection and one of its children. A confirmation discloses transfer of selected draft copy, approved knowledge and writing instructions to OpenAI and the possible API charge. No request is sent on cancellation. The AI panel retains its brief, task and selected proposal while switching editor tabs; a full reload is not a saved brief.

The request captures the saved revision, allowed typed fields, up to six approved source excerpts with provenance/digests, instruction version, and up to twenty actual published link candidates. Results record provider/model, status, error, confirmed token usage when available and timestamps. Unknown fields/source IDs/link IDs, malformed/overlarge JSON and invalid content structures become failed history, never an actionable success. Usage is provider-reported or explicitly unknown, not invented currency costs. At most 500 generation records are retained; admins can export and explicitly delete old records. The two history views display the latest 100 entries for their scope.

Compare source and proposed values, review the cited snapshots, then select individual changes and explicitly confirm **Áp dụng mục đã chọn**. The server rechecks current permissions, proposal/document versions, selected original values, source approval/expiry and instruction version. Indexed paragraphs/list items are also bound to a digest of their parent collection, preventing application to a reordered item even if placeholder text is identical. Earlier selected applications from the same proposal update only their own collection guard; unrelated remote edits remain protected. Saving the draft, marking applied fields, revision history and audit all commit together. Public content is unchanged until a separate authorized publication. SEO users can generate/apply metadata only; editor/admin users can change copy. Viewers have no AI access; only admins may delete history.

Generation and connectivity probes share the daily budget and single request lease. Every dispatch uses an independent lease nonce. Caller-generated request IDs support network recovery without automatic paid retries: a known ID returns its history, while a changed body/actor is rejected. Operational request receipts survive history deletion and website restore, so a deleted paid request cannot be dispatched again under the same ID. Receipts contain no prompt/output/credentials, are excluded from portable exports and are not automatically pruned; the installation cap is 100,000 receipts and requires an operator-reviewed migration before exhaustion. Do not remove receipts as routine history cleanup.

After an ambiguous generation response, use **Kiểm tra kết quả yêu cầu** or the history view before creating another request. A lost apply response is reconciled against the stored applied-field list and saved document. A changed draft/source requires rechecking or generating again, not overwriting another editor. Expired jobs appear interrupted; configuration/session changes during a provider call discard the proposed output. Restored histories remain visible but cannot apply. The actual provider may have charged an interrupted call, so conservative budget reservations are retained when usage cannot be confirmed.

Controlled-provider tests exercise these workflows without provider network access. A real owner-authorized connectivity and editorial smoke test is still a separate acceptance gate after deployment encryption/origin settings and authorized API credentials are configured. Human business/legal approval and the public noindex release gate remain unchanged.
